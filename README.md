# 셐 스토리 스킵

초대 매크로의 VM·ADB·로그인·스토리 연타 구현을 가져온 독립 프로젝트입니다. 원본 폴더와 설정에 의존하지 않습니다.

## 시작

- **전체 이벤스**: 필터가 있는 스토리 목록 또는 읽던 스토리에서 이어 읽습니다. 완독하면 다음 이벤스로 이동합니다.
- **전체 버라**: 버라 미시청 필터를 적용하고 현재 선택부터 각 이벤스의 좌하단 버라를 엽니다. 입장 후 카운트다운을 포함해 총 15초 기다리고 좌상단 나가기를 누릅니다. 보상 스탬프 종류와 관계없이 좌하단 배너의 `参加済み` 글자를 확인하면 성공으로 처리하고 다음 이벤스로 이동합니다. 잠금 아이콘이나 잠금 안내가 나오면 스토리를 읽지 않고 건너뜁니다. 목록을 조금 아래로 스크롤해 다음 이벤스를 선택하며, 잠긴 버라를 시청 완료로 기록하지 않습니다. 처음 계정의 안내는 우상단 `…`가 보일 때만 스킵하며, 조작 안내가 남아 있으면 나가기를 간격 두고 다시 누릅니다.
- **겜 재부팅 후 전체 이벤스**: 선택한 VM의 게임만 종료하고 다시 로그인 → 스토리 목록 → 필터 → 전체 이벤스 읽기를 실행합니다. 계정 초기화와 관계없습니다.
- **1개 이벤스만**: 현재 에피소드 목록의 이벤스만 읽고, 보상 처리와 완독 확인 후 그 화면에서 멈춥니다. 1화가 보여야 한다는 조건은 없습니다. 재접속 후 같은 이벤스가 열렸는지 확인하며, 다른 이벤스면 읽지 않고 중지합니다. 이 모드는 현재 이벤스를 유지하기 위해 RAM 적용을 다음 전체/재부팅 시작으로 미룹니다.

제목 옆에서 앱플레이어를 고르면 그 종류의 인스턴스만 오른쪽에 왼쪽 정렬로 표시합니다. 실행 중인 VM이 하나면 수동으로 켠 VM도 자동 선택하며, 다른 인스턴스는 화면 캡처와 이름으로 직접 선택합니다. 미리보기는 각 VM에서 따로 캡처하고, 매크로 입력은 선택한 한 VM에만 보냅니다. 시작 메뉴는 오른쪽에 있고, 예시 사진을 누르면 크게 볼 수 있습니다.

## 지원 VM과 원본 재사용

| 환경 | VM | 원본에서 가져온 동작 |
|---|---|---|
| Windows | LDPlayer 9 | ldconsole 조회·시작·종료·생성, config 설정, emulator ADB serial, event2 printf 연타 |
| Windows | MuMu | MuMuManager JSON·설정·생성, 인스턴스별 ADB 포트, 세로 축 터치 |
| Windows | BlueStacks 5 | bluestacks.conf·HD-Player·ADB 포트, 32767 축 터치 |
| Windows | MEmu | memuc·설정·Android 9 생성, VM 파일의 ADB 포트, 터치 장치 탐색 |
| Windows | Nox | NoxConsole·설정·Android 12 생성, VM 파일의 ADB 포트, type A 터치 |
| macOS / Apple silicon | BlueStacks Air | 프로세스·설정·ADB 탐색, open/TERM, Virtual Touch 연타, WKWebView, Vision OCR |

`Emulators/`의 각 파일은 원본의 같은 이름 파일에서 가져왔습니다. 초대·리셋·삭제·복제 경로는 포함하지 않았습니다. 상단 **인스턴스 생성**에서 VM 종류와 이름을 선택합니다. 생성 전 디스크 필요량은 **14GB**로 검사합니다. 새 VM의 RAM은 PC 여유에 맞춰 **3~8GB 자동 선택**합니다. BlueStacks는 원본과 같이 멀티 인스턴스 매니저에서 생성합니다. 새 VM의 게임 설치와 계정 로그인은 사용자가 진행합니다.

Windows에서 뮤뮤 외의 앱플레이어를 선택하면 앱플레이어 선택칸 아래에 뮤뮤 권장 문구와 작은 다운로드 링크를 표시합니다. 지원 VM이 없으면 설치 링크부터 표시합니다. macOS는 원본이 지원하는 BlueStacks Air 설치 링크를 제공합니다.

상단 언어 버튼에서 한국어·일본어·영어를 선택합니다. 선택은 다른 접속 화면과 공유되고 다음 실행에도 유지됩니다.

상단 **원격 접속**에서 원격 접속과 포트를 설정하고 접속 주소를 복사합니다. 같은 네트워크의 휴대폰/PC에서 같은 화면을 사용할 수 있습니다. 원본의 LAN 주소 선택과 설정 유지 방식을 재사용하며, 친초 매크로와 함께 사용할 수 있게 기본 포트는 **8788**입니다. 원격 접속 설정은 이 PC의 로컬 창에서 변경합니다.

원본과 같은 960×540 / DPI 160 설정을 사용합니다. 실행 중 잘못된 해상도는 원본의 종료 → 설정 → 시작 흐름을 사용합니다. BlueStacks는 실행 중 공유 설정 파일을 덮어쓰지 않습니다. Google 로그인 창의 Android 뒤로가기도 원본 흐름을 사용합니다.

RAM은 PC 여유 메모리 안에서 3–12GB, 자동 기본 목표 8GB입니다. 설정 키와 단위는 VM별 원본 구현을 사용하며 CPU 수를 유지합니다. 다른 BlueStacks가 켜져 있으면 공유 파일의 RAM 변경을 건너뜁니다.

## 읽기와 복구

- 목록은 우하단 결정 버튼 + 필터로 인식합니다. 완독률 OCR은 표시용이며 진행 조건이 아닙니다.
- 미읽음/SKIP 필터를 적용하고 다른 캐릭터 체크를 해제합니다.
- 현재 위치에서 **아래로만** 검사합니다. 새 스토리 또는 SKIP이 있으면 읽고, 끝까지 두 표시가 없으면 완독입니다. 화 번호·화 수 조건과 위로 되감기는 없습니다.
- 월드링크 목록의 `i` 아이콘 위치 차이도 원본의 ±2픽셀 허용 범위로 인식합니다.
- 연타는 원본의 VM별 축·pressure·tracking·32/64bit·printf/cat 분기를 사용합니다. 화면 감시와 1초짜리 장치 측 입력 허가는 유지하며, `…`가 사라지면 연타를 멈춥니다.
- 자동 재개 시 게임 종료/새 데이터는 반복 복구합니다. 알 수 없는 상태만 실패 횟수를 세며, 스토리 목록 재진입에 성공하면 초기화합니다. 재진입 성공 없이 두 번 실패하면 중지합니다.
- 계정 탈퇴·데이터 초기화·신규 계정 튜토리얼·초대·가챠·VM 삭제 기능은 없습니다. ADB 입력은 선택한 장치와 확인된 화면에만 전송합니다.
- 선택한 인스턴스에서 계정 삭제 확인창, 우상단 크리스탈·유상 표시가 있는 가챠 화면, 카드 상세 화면, 데이터 삭제·인계가 있는 타이틀 메뉴를 감지하면 클릭하지 않고 ADB로 게임을 강제 종료·재실행합니다. 시작 버튼을 눌러 매크로가 실행 중일 때만 감시하며, 대기·중지 상태에서는 게임에 개입하지 않습니다. 실행 중의 보호 동작은 자동 재개 설정과 별개로 작동합니다. 기존 계정 데이터는 유지합니다.

## 실행 및 빌드

Windows: `dist/SekaiStorySkip/SekaiStorySkip.exe`

```powershell
./build-release.ps1
dotnet run --project SekaiStorySkip.csproj -- check-safety
dotnet run --project SekaiStorySkip.csproj -- list
```

인스턴스 번호는 원본과 같습니다: LD 0부터, MuMu 1000부터, BlueStacks 2000부터, MEmu 3000부터, Nox 4000부터. 맥의 Air는 0부터입니다. 기존 MuMu 진행 기록은 새 번호로 옮기고 원본 기록은 `artifacts/legacy-mumu`에 보존합니다.

macOS: .NET 10 SDK와 Xcode command line tools가 있는 맥에서 `bash build-release-mac.sh`를 실행하면 `dist/mac/SekaiStorySkip.app`을 만듭니다. 포트와 앱 식별자, 저장 폴더는 초대 매크로와 분리됩니다. 맥의 설정과 기록은 `~/Library/Application Support/SekaiStorySkip`에 저장합니다.

현재 검증: Windows의 LDPlayer·BlueStacks 5·MEmu·Nox에서 게임 시작과 로그인, 필터 적용, 이벤스 완독, 다음 이벤스 재생까지 확인했습니다. 중지·재시작 원인과 수정 내역은 `artifacts/vm-compatibility-report.json`에 기록했습니다. Windows 검사 297개, macOS용 C# 빌드와 공통 인식·VM 검사 108개를 통과했습니다. macOS 네이티브 앱과 BlueStacks Air의 실제 게임 실행은 별도 확인이 필요합니다.

계정 삭제창의 실제 캡처로 확인하는 검사는 대기 중입니다. 중앙 팝업 구분은 테스트용 팝업과 실제 스토리 캡처로 검사했습니다.
